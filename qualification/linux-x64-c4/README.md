# Linux x64 C4 missing-input preparation

Qualification-branch source only. `linux-x64-c4-inputs.yml` has manual dispatch only, one ubuntu24.04 x64 preparation job, no performance/deployment job. Root review precedes push/dispatch. This preparation fills missing reference/image/tool/offline-dependency inputs; it does not build the private32 CLI or authorize a campaign.

The workflow checks out exact cb6 source and e476 upstream, builds one tool image from the pinned Ubuntu amd64 manifest, and runs one owned container. Node26.8.2/Bun1.4.2 archives and pnpm10.21.0 integrity are fixed in Dockerfile/pins.json. Ubuntu package versions are resolved during preparation, then retained by exact dpkg manifest, apt sources, final image ID and full saved image. No subsequent campaign may apt-update or treat the mutable `ubuntu-24.04` runner label as immutable admission.

The original qualified893 native bundle is included in a deterministic2.2MiB local-upload archive with exact archive and complete bundle-file hashes. Original functional/cleanup review receipts accompany it. No qualified-native build or functional suite is invoked; ELF headers and explicit-loader `--list` do not transfer control to its main function.

Only the missing grid-only reference is built: same cb6 native builder and decoder, e476 upstream, b0be grid patch, journal absent. Its existing builder performs one owned native-grid smoke/probe as part of building the reference; all logs/status and container cleanup survive failure. There is no fallback/rebuild retry. Qualified893 is never substituted as the reference.

Outputs: final prep image archive/ID/inspect/history; exact Node/Bun/pnpm/runtime tool hashes; dpkg/apt/compiler/linker/libc provenance; reference bundle/archive/file-mode-symlink ledger; both ELF header/program/dynamic and actual loader-list logs; full offline pnpm store archive/ledger; source/upstream HEAD/tree; reference-builder source closure; runner ImageVersion/CPU topology/affinity/boot/cgroup ancestors including quota/throttle state; Docker client/version/info; exact container identity and cleanup; aggregate artifact SHA256 manifest. Package registry access is preparation-only; dependency install is frozen-lockfile, ignore-scripts and no side-effects cache. Installed source `git diff --exit-code` must remain clean.

The image and reference are uploaded as a14day qualification artifact, not published to a registry/npm. Root then reviews extracted hashes and host topology to populate closed `host-artifact.json`/admission for the existing `.tasks/native-x64-c4/preparation/launch-preparation.py` phase. That later phase builds CLI once, verifies imports/wait4/ELF/full closure and still does not run performance. Final image must be loaded from its reviewed archive and checked against its recorded image ID. Subsequent CPU/idle need new boot/cgroup witnesses, no-CFS-quota ancestor admission, exactly reviewed CPU allocation, and separate timing approval; this preparation records topology without declaring hosted CPUs quiet or dedicated.

Source artifacts are isolated from root production. Candidate comparison scope remains cb6+reviewed private32; production default0/native opt-in and all acceptance budgets remain untouched. Final-cut applicability is separate.

Reference input preflight is mandatory before compilation: exact cb6 hashes for builder, both pure helper modules, decoder, grid patch and COPYING; one grid-only provenance entry; actual pure decoder/helper imports. Four offline fixture tests cover the complete closure, each missing input (including the previously omitted license), altered license and accidental journal provenance. The license is copied and hashed explicitly. Successful ARM72d reference preparation was used to audit required source inputs. All potentially large artifacts in runner/build-inputs use1MiB streaming SHA256; offline extraction tests exercise the actual helper functions over multi-chunk input without importing/executing the preparation entrypoints.
