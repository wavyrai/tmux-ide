A tmux-ide plugin is a small Lua program that adds commands to the palette
(F5 in the TUI, "Plugin commands…" in the Mac app) and to
`tmux-ide action`. Plugins can run programs you allow, read and drive
panes, and keep a little state. They run in the daemon's plugin host,
each with its own Lua state, time limits and memory cap.

Plugins come from two places:

| Where                         | Runs                                                   |
| ----------------------------- | ------------------------------------------------------ |
| `~/.tmux-ide/init.lua`        | Always: it is your own file, like a shell rc           |
| `~/.tmux-ide/plugins/<name>/` | Only after you allow it with `tmux-ide plugin consent` |

## Try the worktree tasks example

The `worktree-tasks` example turns git worktrees into tasks: start one on a
new branch with its own session, open it, list it, remove it. It uses
[`tmux-ide worktree`](/docs/worktrees), so `tmux-ide` must be on the
daemon's `PATH`.

```bash
tmux-ide plugin example worktree-tasks   # copy it into ~/.tmux-ide/plugins/
tmux-ide plugin consent worktree-tasks   # review what it asks for, then allow it
```

Consent shows what the plugin asks to do:

```text
worktree-tasks 1.0.0
Tasks as git worktrees: start, open and remove them from the palette, with tmux-ide worktree.
…
It asks to:
  - run these programs: tmux-ide. A program it may run can usually do anything your account can
```

Then open the palette in a session of the repository and pick **New task**,
**Open task**, **Remove task** or **List tasks**. From a shell inside tmux:

```bash
tmux-ide action run plugin.worktree-tasks.new --arg branch=fix/login
tmux-ide action run plugin.worktree-tasks.remove --arg task=fix/login   # asks to confirm
```

The example works on the repository of the session you run it from. The
palette passes that session in the TUI and the Mac app; the CLI uses the
session of the pane it runs in, or `--session <name>`. It never types into
a pane, so it does not ask for `panes.send`.

## Consent

- Consent covers the plugin's exact files: tmux-ide records a SHA-256 of the
  plugin directory. If any file changes, the plugin stops loading until you
  run `tmux-ide plugin consent <name>` again.
- `tmux-ide plugin revoke <name>` stops the plugin, kills the programs it
  started, and withdraws consent.
- Consent is the security boundary. Allow a plugin only if you trust its
  author, the same way you would before running their shell script.

## Capabilities

A plugin's `manifest.json` lists what it needs under `capabilities`. Consent
shows each one in these words:

| Capability           | Lets the plugin                                                                         | Consent says                                                                               |
| -------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `exec: ["git", …]`   | Run the named programs with `ide.exec`                                                  | "run these programs: git. A program it may run can usually do anything your account can"   |
| `shell: true`        | Run any `/bin/sh` command line                                                          | "run ANY shell command line, with full access to your account"                             |
| `"panes.send": true` | Type into panes, and run a program as if typed in a pane (`ide.exec{ context = "%3" }`) | "type into your terminals and run commands there, which gives full access to your account" |

Every plugin, with no capability, can read what your panes show, list
panes, run tmux-ide's pane and window actions (split, zoom, select, resize,
rename, close), show a notification, and keep up to 1 MiB in its own store.
The manifest also accepts `keys`, `sidebar` and `status` for features that
are not built yet; consent lists them, and they do nothing today.

### What programs a plugin runs can and cannot do

A program a plugin may run can usually do anything your account can: edit
your shell profile, start other programs, use the network. The sandbox
around it is a seat belt, not a wall:

- It cannot write under `~/.tmux-ide`, except the plugin's own
  `~/.tmux-ide/plugin-data/<name>/`, and cannot read the daemon's record,
  claim, consent records, plugin stores or the app settings.
- It is looked up on the daemon's `PATH`, never one the plugin sets, and the
  plugin may set only `LANG`, `LC_*`, `TZ`, `TERM`, colour variables,
  `COLUMNS`, `LINES` and `PLUGIN_*` variables for it.
- It is stopped after its timeout (at most the callback's 30 seconds), and
  when the plugin fails, is reloaded, disabled or revoked.

On macOS the sandbox is `sandbox-exec`. **On Linux, plugins cannot run
programs by default**: the bubblewrap sandbox has not been tested on a real
Linux machine yet. To turn it on anyway, start the daemon with
`TMUX_IDE_PLUGIN_EXEC_LINUX=1`.

## Write a plugin

A plugin is a directory with a manifest and a Lua entry file. This one,
`~/.tmux-ide/plugins/hello/`, has `manifest.json`:

```json
{
  "name": "hello",
  "version": "0.1.0",
  "api": "^1.0",
  "description": "Says hello",
  "capabilities": { "exec": ["git"] }
}
```

and `init.lua`:

```lua
ide.action.register{
  id = "branch",
  title = "Show branch",
  category = "Hello",
  params = { { name = "repo", label = "Repository path" } },
  run = function(ctx, args)
    local r = ide.exec{ cmd = "git", args = { "-C", args.repo, "branch", "--show-current" } }
    return "On " .. r.stdout
  end,
}
```

Then run `tmux-ide plugin consent hello`. `ctx` holds where the command was
run from: `source`, `session` when known, and `pane` (a tmux id like `%3`)
only in the TUI and the CLI. The Mac app does not pass a pane yet.

Reference and helpers:

```bash
tmux-ide lua api                     # every function in the plugin API
tmux-ide lua describe ide.exec       # one function, with an example
tmux-ide lua run -e 'return ide.version'
tmux-ide plugin list                 # the host and each plugin's state
tmux-ide plugin logs hello -f        # follow one plugin's log
tmux-ide plugin reload hello
```

Titles, labels and everything a plugin shows must be plain text: no control
characters, newlines or invisible formatting characters.

## Limits

| Limit                                         | Value                              |
| --------------------------------------------- | ---------------------------------- |
| Lua time per callback                         | 250 ms                             |
| Wall clock per callback (and program timeout) | 30 s                               |
| Memory per plugin                             | 64 MiB                             |
| Timers per plugin                             | 64 (`every` at least 250 ms apart) |
| Store per plugin                              | 1 MiB, 1000 keys                   |

A plugin that runs past its limits three times within a minute is disabled
until you run `tmux-ide plugin reload <name>`. Commands of one plugin run
one at a time.
