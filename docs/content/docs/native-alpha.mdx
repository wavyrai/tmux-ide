The native alpha brings Home, Terminals and searchable Commands to a macOS
window. It connects to the tmux-ide daemon that owns your tmux sessions.
The terminal app remains available alongside it.

**Public alpha — version 0.1.2, build 2026101702.** The app is Developer ID
signed and Apple notarized. Private real-SSH recovery, native two-pane reconnection/input and packaged-app checks passed; a fresh second-Mac test remains outstanding. Expect alpha bugs and
keep the terminal app available as a fallback.

This build automatically reconnects an already-open terminal after a transient
connection loss when the same machine, tmux server, session and pane can be
verified again. Input entered while disconnected is discarded, and leaving for
Home cancels recovery. The original cause of reported Spark connection drops
remains under investigation.

## Requirements

- **Apple Silicon and macOS 26 or later** for the complete one-Mac setup below,
  including the CLI/daemon. The native app itself declares macOS 14.2 as its
  minimum; that alone does not establish full setup support on older macOS.
- **tmux-ide CLI/daemon 2.9.6** for the current managed installation.
  This candidate was exercised with an isolated development daemon; a separate
  fresh-machine compatibility check remains outstanding. The app bundles its own
  Node.js runtime. The installer requires the managed Node 24 supplied by the
  [universal CLI installer](/docs/getting-started#install).
- Claude Code or Codex on the target machine if you use **New agent**. Opening
  existing terminals does not require either harness.

This alpha does not provide an Intel Mac, Windows or Linux native app.

## Download and install

The [alpha release notes](https://github.com/wavyrai/tmux-ide/releases/tag/native-alpha-2026101702)
and [signed Apple Silicon archive](https://github.com/wavyrai/tmux-ide/releases/download/native-alpha-2026101702/tmux-ide-gpui-0.1.2-macos-arm64.app.tar.gz)
include the exact signed build used by the installer.

Install the native alpha with one command. This also installs CLI 2.9.6 at
`~/.local` when the managed CLI is missing, or upgrades an older stable version.
An existing 2.9.6 installation is preserved. Newer or unrecognized CLI versions
are left untouched and require explicit review before native installation:

```bash
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha
```

The native installer verifies pinned download checksums and the app's Apple
signing identity. It installs under your user account, without sudo, and does
not open the app. The CLI step restarts a running older daemon on the managed CLI
and repoints a launchd job that starts an older tmux-ide copy, keeping your tmux
sessions running. It does not start a daemon that is not running. Start one, or
retry an update, explicitly:

```bash
~/.local/bin/tmux-ide update --daemon --json
```

Open **Tmux IDE Alpha** from your user **Applications** folder in Finder:

```text
~/Applications/Tmux IDE Alpha.app
```

You can keep it in the Dock after opening it. This entry points to the managed
installation under `~/Library/Application Support/tmux-ide/native-alpha`, where
versions are retained for update and rollback. Leave that managed directory in
place. The installer preserves any unrelated app or link already using the
Applications name; follow its message if that name is occupied.

If macOS rejects the app's signature or says it is damaged, stop and report the
build and message. Do not remove quarantine attributes or disable Gatekeeper to
make an unexpected download run.

## First session

If you have no sessions yet, select **Local** and its **Default** server on
Home, choose **New session…**, enter a name and select **Create**. Open that
session to get a shell.

On **Home**, browse your machines and sessions, or select an available agent.
**Terminals** shows the selected session's windows and panes. Names can repeat,
so check the machine and server context before selecting a destination.

Open **Commands** with `F5` to search sessions, agents and actions. Its
**Keyboard shortcuts** and **Using tmux-ide** pages describe the native app's
controls. Depending on your macOS keyboard settings, use `Fn` with function keys.

`F8` goes back through accepted session visits; `Shift+F8` goes forward. Open two
different sessions first: no previous visit means there is nowhere to go back.
`F9` cycles retained session tabs. Closing a session tab leaves its tmux session
running; **Close pane** is a separate, destructive action with confirmation.

Use the native reference pages for this alpha. The [terminal app tour](/docs/app-surfaces) provides additional context for
Home and Terminals; native controls can differ.

## Update, roll back or uninstall

Quit the native app before changing its installation. These explicit actions do
not stop the daemon or tmux sessions. Updating the CLI does not update the native
bundle, and the alpha installer currently selects the pinned build above rather
than an automatic update channel.

```bash
# Install the alpha selected by the published installer
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --update

# Restore the previous retained, verified native build
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --rollback

# Detach the native app, retaining version files and configuration
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --uninstall
```

Keep `--native-alpha` first. On the initial installation there is no previous
build: rollback refusing in that case is expected. Reinstalling the same pinned
build does not create a new rollback destination.

Rollback changes the native app only, not the daemon or preference data. Check
the older build's daemon requirements before using it. Do not delete settings
or restart/kill tmux servers as an installation step. Quitting the client is
separate from **Close pane** or stopping a session.

## Troubleshooting

**Home stays on “Loading sessions” or no sessions appear.** Check that a
compatible daemon is running with `tmux-ide daemon info --json`, and run
`tmux-ide doctor --json`. Record whether the app changes after you bring its
window to the foreground. A window that updates only after a click is a bug worth
reporting; an empty agent list alone does not mean your sessions have stopped.

**Back or Forward does nothing.** First visit two distinct sessions and wait for
each terminal to appear. Use the action in Commands to distinguish function-key
handling from an unavailable history destination.

**A machine or agent is unavailable.** Check the displayed connection state and
[remote-machine setup](/docs/remote-machines). Retry through the app once the
connection is restored. Do not recreate the session merely to clear a status.

**The window is narrow or text is hard to read.** Try a larger window and use
Commands to change the terminal font or theme. Report clipped controls with the
window dimensions and macOS display scaling. Include whether scrolling, resizing
or switching sessions caused it.

## Report a bug

Open an issue in the [tmux-ide issue tracker](https://github.com/wavyrai/tmux-ide/issues)
and include:

- Native version and build number, CLI version (`tmux-ide --version`), macOS
  version and Mac architecture.
- The shortest steps to reproduce, expected behavior and what actually happened.
- Whether the session was local or remote, and whether the problem followed an
  update, reconnect, resize or background/foreground transition.
- Relevant `tmux-ide doctor --json` output and a screenshot or short recording
  when it helps explain the problem.

Review diagnostics before sharing them. Remove tokens, credentials, private
paths and terminal contents you do not want to publish. Do not attach raw daemon
discovery files. See [Troubleshooting](/docs/troubleshooting) for CLI checks.
