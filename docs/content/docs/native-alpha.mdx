The native alpha brings Home, Terminals and searchable Commands to a macOS
window. It connects to the tmux-ide daemon that owns your tmux sessions.
The terminal app remains available alongside it.

**Public alpha — version 0.1.16, build @BUILD@.** The app is Developer ID
signed and Apple notarized, and its packaged-app checks passed; a fresh second-Mac test remains outstanding. Expect alpha bugs and
keep the terminal app available as a fallback.

With a 2.9.22 daemon, this build shows images that programs in tmux panes send
with the kitty graphics protocol (Unicode placeholder images; cursor-placed images
are best effort). It also refreshes the selected pane after pane splits.
Terminal dimensions remain stable when the app loses focus; another attached
tmux client can still take over sizing.

This build reduces work when updating terminal contents and images, and keeps
terminal dimensions steady while connection-status text changes. After switching
panes, immediate typing is held briefly until the selected pane is confirmed.
If its identity changes before delivery, input is interrupted: reselect the pane
and retype the command. Interrupted input is never automatically replayed.

Normal GUI startup now owns discovery, catalogs, agent operations and SSH in
Rust. Terminal updates apply changed rows while retaining unchanged content.
Image queues and local native pixel storage are bounded. The managed terminal browser is bundled with this alpha. `tmux-ide open [url]`
discovers it from the standard native installation. The pane header provides
back/forward, reload/stop and a Cmd-L address editor. The optional upstream
`action` automation helper is not bundled.

In 0.1.16, the window follows the reviewed design more closely. The sidebar is 252 pt wide
and lists the open project first, then favourites, then the rest by name. The focused pane
is painted in the terminal's background colour and the other panes one small step toward the
text colour, so focus shows by fill rather than by an outline. A new terminal uses 12 pt type
on a 15 pt line; a font size you saved still wins. The sidebar is frosted glass in light and
dark mode, with a density chosen per theme; Blue, Pink, Purple, Red, Solarized and Solarized
Light stay opaque, and Reduce transparency or Increase contrast turns the glass off. Its
footer holds Switch session and Switch machine on the left, and Choose theme and Settings and
commands (F5) on the right. With the sidebar shown, the traffic lights, the sidebar toggle,
search and New session head the sidebar, and the pane cards start just under the window's top
edge. With the sidebar hidden, that row shrinks to the traffic lights' height. Menus, dialogs,
Home's new rows and the sidebar move with short animations, and none when Reduce motion is on.

In 0.1.16, `tmux-ide open notes.md` with CLI 2.9.22 shows the file in a native, read-only
[Markdown reader](/docs/markdown-reader). Drag a pane's header title onto another pane in the
same window to swap the two panes; Esc cancels the drag and Cmd-Z swaps them back. Closing a
pane asks in a small card under its close button and says what ends: an agent at work stops
mid-turn, and for Claude Code and Codex the card names the command that resumes the
conversation. Cancel is the default button; press Cmd-W again to close.

In 0.1.16, reconnecting is quiet. A drop shorter than 2 s changes nothing on screen. Then a
spinner shows in the middle of the sidebar footer, after 8 s "Reconnecting…" with pane titles
dimmed, and after a minute "Offline since" a time, which you can click to retry. A key typed
while the connection is down shows "Not sent" in its pane and is never replayed later. Agents
and Home's list stay as they were during a drop; after 8 s agent marks are dimmed and a
waiting agent reads "Needs input · last known". Problems only you can fix, such as a daemon
that needs an update or a missing setup step, show at once as one card on Home with its
action and Copy details. A remote machine that drops keeps its last known sessions listed,
retries by itself up to once a minute until you disconnect it, and says "Unreachable since"
a time after a minute. A session window reconnects by itself after the daemon restarts or
updates, and an SSH session window does too after the remote daemon updates, as long as the
same tmux server and session are still running there. If tmux-ide was updated in a way this
app can't talk to, the window says to update the app.

In 0.1.16, Home's "Set up local sessions" works with CLI 2.9.6 and every later 2.9 release.
Earlier builds accepted only CLI 2.9.6 through 2.9.12 and called any newer CLI "not supported
for automatic setup". Home now says which problem it found: a CLI version this app can't set
up, or an installation it doesn't recognize. Copy diagnostics names the same problem.

Also in 0.1.16: typing straight after a split goes to the new pane instead of interrupting
input; an action's result, such as the editor's answer to Open folder in VS Code, stays in
the status line until your next command; and a session with more than 24 panes no longer
breaks Home. Home lists it as "too many" and says what to do.

0.1.16 asks daemons for a newer pane-stream capability that includes the reader. Until a
remote machine runs CLI 2.9.22, its daemon sends this app no browser favicons and sends
terminal graphics uncompressed. Everything else works as before.

In 0.1.15, Home reconnects by itself when its connection to the
daemon drops, as it does when the daemon restarts or updates, stops, or stalls while a Mac
sleeps. The session list stays on screen with a quiet "Reconnecting…" line, and Home retries
with backoff up to every 5 s while it is in front. Home shows a warning only for a failure
that won't recover by itself, and says why: a daemon that needs an update, refused
credentials, or an unreadable daemon record. Earlier builds showed "Catalog connection
changed — refresh to reconnect" and "The daemon could not list sessions" until you refreshed.
This corrects the 2.9.16 notes: their claim that the session catalog reconnects after a single
error was true only for the terminal stream, not for Home.

In 0.1.15, the app has a new look. The default System theme paints Linen in light mode and
Linen Dark in dark mode. Panes are cards with a one-line header (split right, split down, zoom
and close), the sidebar groups panes by project with one row per pane, and Home lists your
agents with a chip for each one that needs input. With CLI 2.9.21, the palette also lists
[plugin](/docs/plugins) commands under "Plugin commands…".

In 0.1.14, the app retries a lost pane layout read, so dividers between panes come back without
resizing the window.

With CLI 2.9.18 or newer, this build also shows pane dividers on a tmux server started by
Homebrew's or another stock tmux, and from 2.9.20 on one started by an older tmux-ide tmux.
See [What's new in 2.9.20](/docs/release-2-9-20).

The default theme, System, now follows macOS with Linen, a warm light theme, and
Linen Dark. Light, Dark and every other preset stay in Commands → Appearance….
"Working" is shown in a muted colour, so the theme's one accent marks only an agent
that needs input. Each pane header is one line: the title on the left, and split
right, split down, expand and close on the right. Right-click (or Control-click) a
pane's title for the pane menu. From the keyboard or with VoiceOver, F5 lists every pane
action, including Open folder in VS Code.

The sidebar lists sessions by project. The open project lists one row per pane, under a
heading for each window when it has more than one, with an icon for what runs there
(Claude, Codex and other agents, Neovim, a shell) and the agent's task title or name. A
working agent shows a spinner and one that needs input a "Needs input" pill. Other
projects list their agents. Hover a pane row for its … menu, or right-click it; from the
keyboard, Ctrl-G to the row, then Shift-F10. VoiceOver can press the row's … button, and
F5 lists every pane action. Windows moved from the title bar into the sidebar. The row
beside the traffic lights holds the sidebar's controls: show or hide the sidebar, browse
sessions, and New session. Home is the sidebar's first row (F1), and joins that row when
the sidebar is hidden. New Window is in the menu bar (Cmd-T). Machines, servers and
their actions are on Home.

Home keeps the sidebar beside its table when the window is wide enough. Its toolbar holds
the title, Browse sessions, the needs-input pill, Refresh, and New session in the theme's
accent; Choose Theme… is in the menu bar, F5 and the sidebar footer. One row of filters
over the table picks all sessions, favourites, or one machine, and Add machine…. Agents
have their own column: each is a chip with its mark and state, and one that needs input
wears the accent. A status line or a fault's banner shows under the toolbar, above the
filters.

In 0.1.13, the app has a new icon, with light and dark versions on macOS 26, and its UI
picks up new app state when it arrives instead of on a 16 ms tick. The installer now gives up
on a stalled download rather than a slow one. See [What's new in 2.9.17](/docs/release-2-9-17).

In 0.1.12, the app stays connected: a pane whose update is rejected is asked
for again while the others keep running, and a dropped stream reconnects with
backoff, showing the last frame read-only with a "Reconnecting…" badge. Keys
typed during a drop are refused, never replayed. Home is one table of sessions
grouped by machine, with each project's favicon, windows, panes, last activity
and the session's agent state; a "needs input" pill shows only the sessions
whose agent waits. The app no longer bundles Node.js; the browser runs on its
own engine. `tmux-ide open` now says when the browser it starts has no tmux-ide
controls. See [What's new in 2.9.16](/docs/release-2-9-16).

Pane gutters share the surrounding app background. Native browser
controls remain in the pane header while the app is in the background, disabled
until input authority returns. The terminal toolbar no longer reappears
because native control polling pauses.

Windows are listed in the sidebar under the open project, and selection progress does
not insert a notice in the top bar.
Keyboard controls include Cmd-T for a new window, Cmd-D / Cmd-Shift-D for splits,
and Cmd-Shift-[ / ] for window switching.

These changes do not establish a measured latency improvement or continuous
scrolling parity with the terminal app.

Upgrade, repeat installation and rollback from public alpha 0.1.9 passed in an isolated installation.
One foreground-return anomaly occurred during signed-app testing and did not
reproduce in two follow-up runs; it remains under investigation.

The app automatically reconnects an already-open terminal after a transient
connection loss when the same machine, tmux server, session and pane can be
verified again. Input entered while disconnected is discarded, and leaving for
Home cancels recovery. The original cause of reported Spark connection drops
remains under investigation.

## Requirements

- **Apple Silicon and macOS 26 or later** for the complete one-Mac setup below,
  including the CLI/daemon. The native app itself declares macOS 14.2 as its
  minimum; that alone does not establish full setup support on older macOS.
- **tmux-ide CLI/daemon 2.9.22** for the current managed installation.
  A separate fresh-machine compatibility check remains outstanding. The app itself
  bundles no Node.js. The installer requires the managed Node 24 supplied by the
  [universal CLI installer](/docs/getting-started#install).
- Claude Code or Codex on the target machine if you use **New agent**. Opening
  existing terminals does not require either harness.

This alpha does not provide an Intel Mac, Windows or Linux native app.

## Download and install

The [alpha release notes](https://github.com/wavyrai/tmux-ide/releases/tag/native-alpha-@BUILD@)
and [signed Apple Silicon archive](https://github.com/wavyrai/tmux-ide/releases/download/native-alpha-@BUILD@/tmux-ide-gpui-0.1.16-macos-arm64.app.tar.gz)
include the exact signed build used by the installer.

Install the native alpha with one command. This also installs CLI 2.9.22 at
`~/.local` when the managed CLI is missing, or upgrades an older stable version.
An existing 2.9.22 installation is preserved. Newer or unrecognized CLI versions
are left untouched and require explicit review before native installation:

```bash
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha
```

The native installer verifies pinned download checksums and the app's Apple
signing identity. It installs under your user account, without sudo, and does
not open the app. The CLI step restarts a running older daemon on the managed CLI
and repoints a launchd job that starts an older tmux-ide copy, keeping your tmux
sessions running. It does not start a daemon that is not running. Start one, or
retry an update, explicitly:

```bash
~/.local/bin/tmux-ide update --daemon --json
```

Open **Tmux IDE Alpha** from your user **Applications** folder in Finder:

```text
~/Applications/Tmux IDE Alpha.app
```

You can keep it in the Dock after opening it. This entry points to the managed
installation under `~/Library/Application Support/tmux-ide/native-alpha`, where
versions are retained for update and rollback. Leave that managed directory in
place. The installer preserves any unrelated app or link already using the
Applications name; follow its message if that name is occupied.

From 0.1.16 the app is named Tmux IDE in the Dock, the app switcher, Spotlight and
the menu bar; the entry in your Applications folder keeps the name Tmux IDE Alpha,
and updates keep your settings and permissions.
The app menu's first item, About Tmux IDE, shows the app's version and build and
the tmux-ide version it is connected to, with Copy diagnostics.

If macOS rejects the app's signature or says it is damaged, stop and report the
build and message. Do not remove quarantine attributes or disable Gatekeeper to
make an unexpected download run.

## First session

If you have no sessions yet, select **Local** and its **Default** server on
Home, choose **New session…**, enter a name and select **Create**. Open that
session to get a shell.

On **Home**, browse your machines and sessions, or select an available agent.
**Terminals** shows the selected session's windows and panes. Names can repeat,
so check the machine and server context before selecting a destination.

Open **Commands** with `F5` to search sessions, agents and actions. Its
**Keyboard shortcuts** and **Using tmux-ide** pages describe the native app's
controls. Depending on your macOS keyboard settings, use `Fn` with function keys.

`F8` goes back through accepted session visits; `Shift+F8` goes forward. Open two
different sessions first: no previous visit means there is nowhere to go back.
`F9` cycles retained session tabs. Closing a session tab leaves its tmux session
running; **Close pane** is a separate, destructive action with confirmation.

Use the native reference pages for this alpha. The [terminal app tour](/docs/app-surfaces) provides additional context for
Home and Terminals; native controls can differ.

## Update, roll back or uninstall

Quit the native app before changing its installation. These explicit actions do
not stop the daemon or tmux sessions. Updating the CLI does not update the native
bundle, and the alpha installer currently selects the pinned build above rather
than an automatic update channel.

```bash
# Install the alpha selected by the published installer
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --update

# Restore the previous retained, verified native build
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --rollback

# Detach the native app, retaining version files and configuration
curl -fsSL https://tmux-ide.com/install.sh | sh -s -- --native-alpha --uninstall
```

Keep `--native-alpha` first. On the initial installation there is no previous
build: rollback refusing in that case is expected. Reinstalling the same pinned
build does not create a new rollback destination.

Rollback changes the native app only, not the daemon or preference data. Check
the older build's daemon requirements before using it. Do not delete settings
or restart/kill tmux servers as an installation step. Quitting the client is
separate from **Close pane** or stopping a session.

## Troubleshooting

**Home stays empty or no sessions appear.** From 0.1.16, Home shows no
“Loading sessions” text; a spinner or “Reconnecting…” in the sidebar footer means
the app is still trying, and a card on Home names a problem only you can fix. Check that a
compatible daemon is running with `tmux-ide daemon info --json`, and run
`tmux-ide doctor --json`. Record whether the app changes after you bring its
window to the foreground. A window that updates only after a click is a bug worth
reporting; an empty agent list alone does not mean your sessions have stopped.

**Back or Forward does nothing.** First visit two distinct sessions and wait for
each terminal to appear. Use the action in Commands to distinguish function-key
handling from an unavailable history destination.

**A machine or agent is unavailable.** Check the displayed connection state and
[remote-machine setup](/docs/remote-machines). Retry through the app once the
connection is restored. Do not recreate the session merely to clear a status.

**The window is narrow or text is hard to read.** Try a larger window and use
Commands to change the terminal font or theme. Report clipped controls with the
window dimensions and macOS display scaling. Include whether scrolling, resizing
or switching sessions caused it.

## Images after an upgrade

Updating the CLI or daemon leaves existing tmux servers and their shells running.
A server started by an older tmux binary continues using that binary, even after
its file on disk has been replaced. Image support therefore depends on the
running server as well as the installed CLI.

Open the session in the native app before starting an image-capable program.
The daemon enables graphics on supported servers and sets
`TMUX_IDE_GRAPHICS=kitty` for new shells. A shell that was already running does
not inherit that environment change; in that shell, run:

```bash
export TMUX_IDE_GRAPHICS=kitty
```

This advertises support to the program; it does not add graphics support to an
older or stock tmux server. From a shell inside the affected session, check the
server's graphics option with `tmux show-options -gv kitty-graphics`. If `tmux`
is not on PATH, the managed Apple Silicon installation includes it at:

```bash
~/.local/share/tmux-ide/current/npm/lib/node_modules/tmux-ide/packages/daemon/dist/native/tmux/darwin-arm64/tmux show-options -gv kitty-graphics
```

An unknown-option error means that server does not have the graphics extension.
An `on` result confirms the extension is enabled, but does not identify its patch
version. Older patched servers can still lack newer media-query and sizing fixes.
Use a newly created server with the updated bundled tmux for those fixes. Plan
any retirement of an old server around its running work: killing a tmux server
ends its shells and agents. The installer does not restart it automatically.

## Report a bug

Open an issue in the [tmux-ide issue tracker](https://github.com/wavyrai/tmux-ide/issues)
and include:

- Native version and build number, CLI version (`tmux-ide --version`), macOS
  version and Mac architecture.
- The shortest steps to reproduce, expected behavior and what actually happened.
- Whether the session was local or remote, and whether the problem followed an
  update, reconnect, resize or background/foreground transition.
- Relevant `tmux-ide doctor --json` output and a screenshot or short recording
  when it helps explain the problem.

Review diagnostics before sharing them. Remove tokens, credentials, private
paths and terminal contents you do not want to publish. Do not attach raw daemon
discovery files. See [Troubleshooting](/docs/troubleshooting) for CLI checks.
