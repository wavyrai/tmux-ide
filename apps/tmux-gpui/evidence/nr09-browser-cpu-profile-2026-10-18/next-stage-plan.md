# Separate publication-stage attribution proposal

Do not modify product or the frozen baseline payload. Copy the fixed browser bundle into a private sibling directory alongside unchanged live bundle, record original and instrumented hashes and exact textual transformation. Independent review before one instrumented correctness run.

Preserve publish evaluation order: mark function entry; immediately before its existing JSON.stringify object literal, mark envelope start; assign that exact literal to a local envelope; mark envelope end; stringify envelope plus newline; mark stringify end; perform original byteLength/limit check; mark sizing end; perform original pending assignment or stdout.write; mark enqueue/write end. Record numeric monotonic durations, request, sequence, frame kind, byte count and blocked/enqueued flag only. A separate drain record measures the deferred write call. Keep records in a bounded array (e.g. 2048) and write once on graceful shutdown to private file; overflow marks incomplete attribution, never affects protocol. Write-call duration is enqueue cost, not flush/display completion. All browser publication metadata and ordering remain unchanged.

Reuse correctness harness: exact A/B/A, inert previews, fresh input, source/PID survival, cleanup and hashes. Profiled timings cannot replace baseline. Compare stage totals within this separate instrumented run, retain startup/warmup distinction and no native inference. No product optimization until stage evidence and review establish an appropriate owner.

Potential later serialization reuse requires immutability proof, not only equal text or tab identity. Current retained-frame-cache stores bounded serialized strings, then preview JSON.parse returns fresh snapshot objects. Browser assigns coherent.snapshot and typically replaces/nulls it rather than mutating it, but nested alias ownership is not yet exhaustively established. JSON.rawJSON availability in qualified Node24 must be checked locally. Any reuse must preserve every envelope, sequence, request, current authority and size/backpressure validation; cache lifetime and bounds must follow exact snapshot identity/owner. No implementation of rawJSON or publication suppression is authorized by this profiling proposal.
